Para desarrolladores

Documentación de Luminis

Todo lo necesario para conectar tus aplicaciones a la red de Luminis: abrir el socket, publicar cualquier tipo de dato, seguir su entrega y usar la API REST desde tu backend.

WebSocketws://localhost:8081/socket
API RESThttp://localhost:8081/api/luminis
API key

Llave secreta lm_… que identifica tu cuenta. Cada una tiene sus propios permisos y se crea desde tu área de cliente.

Usuario

Identificador libre de quien se conecta: una persona, un sensor, una pantalla o un servidor. Ejemplos: ana, sensor-01, dashboard.

Evento

Cualquier JSON o texto que envías a un destino. Luminis no interpreta su contenido: solo lo entrega.

Destino

El usuario que debe recibir el evento. Si tiene varias conexiones abiertas, todas lo reciben.

Inicio rápido

  1. Crea tu cuenta y activa un plan.Sin plan vigente las conexiones se rechazan con el código 4402.
  2. Crea una API key.En tu área de cliente: Configuración → API keys. Para el socket necesitas al menos conectar y enviar.
  3. Abre el socket y publica.Conecta con tu llave y el nombre del usuario, y envía tu primer evento.
JavaScript · navegador
const socket = new WebSocket("{{WS}}?apikey=lm_TU_CLAVE&usuario=sensor-01");

socket.onopen = () => console.log("Conectando…");

socket.onmessage = (e) => {
  const evento = JSON.parse(e.data);
  if (evento.type === "ready") {
    socket.send(JSON.stringify({
      type: "message",
      destino: "dashboard",
      mensaje: { temp: 23.4, hum: 61 }
    }));
  }
  console.log(evento.type, evento);
};

Probar con Postman

Postman permite abrir conexiones WebSocket sin escribir código. Es la forma más rápida de verificar que tu API key y tu plan funcionan.

  1. New → WebSocket.Pega la URL de conexión y pulsa Connect:
URL
{{WS}}?apikey=lm_TU_CLAVE&usuario=sensor-01
  1. Recibirás el evento ready.Confirma que la conexión está autenticada e incluye los límites de tu plan.
  2. Abre otra pestaña WebSocket con usuario=dashboard.Desde la primera, escribe este mensaje en el panel Message y pulsa Send:
JSON
{ "type": "message", "destino": "dashboard", "mensaje": { "temp": 23.4, "hum": 61 }, "ref": "prueba-1" }

La primera pestaña recibe sent y delivered; la segunda recibe message con un mensajeId. Si cierras la segunda y vuelves a enviar, el evento queda en la cola offline y llega en cuanto reconectas.

También puedes probarlo sin Postman desde la Consola de tu área de cliente, que abre un socket real desde el navegador.

Conexión

URL
{{WS}}?apikey=<API_KEY>&usuario=<USUARIO>
ParámetroRequeridoDescripción
apikeySíTu API key con el permiso conectar. También puede enviarse en el encabezado X-Api-Key cuando tu cliente WebSocket lo permita.
usuarioSíDe 1 a 80 caracteres: letras, números y . _ @ : -. Es el nombre con el que otros te enviarán eventos.

Al aceptar la conexión, Luminis envía el evento ready:

Evento recibido
{
  "type": "ready",
  "usuario": "sensor-01",
  "sesion": "8c1f2a90b3d4",
  "protocolo": "2",
  "limites": {
    "plan": "Destello",
    "peticionesMes": 500000,
    "conexiones": 100,
    "mensajeKb": 64,
    "retencionSegundos": 3600
  }
}

Un límite null significa ilimitado. Un mismo usuario puede tener hasta 20 conexiones abiertas a la vez (por ejemplo, el móvil y el ordenador); todas reciben sus eventos.

Enviar eventos

Envía un objeto JSON con type: "message". El campo mensaje acepta cualquier valor JSON: objeto, arreglo, número o texto.

Trama a enviar
{
  "type": "message",
  "destino": "dashboard",
  "mensaje": { "pedido": "A-901", "estado": "en_camino" },
  "ref": "mi-id-local-123"
}
CampoRequeridoDescripción
typeNoSi se omite se asume message.
destinoSíUsuario que recibirá el evento (mismas reglas que usuario).
mensajeSíEl contenido. Su tamaño no puede superar el máximo por evento de tu plan.
refNoIdentificador tuyo. Luminis lo devuelve en sent, delivered y en los errores para que relaciones respuestas con envíos.

Requiere el permiso enviar. Cada conexión puede enviar hasta 30 eventos por segundo con ráfagas de 60; por encima se responde el error RATE_LIMIT.

Recibir eventos

Cada conexión del destino recibe:

Evento recibido
{
  "type": "message",
  "mensajeId": "3f9a1c7e2b",
  "origen": "sensor-01",
  "destino": "dashboard",
  "mensaje": { "temp": 23.4, "hum": 61 },
  "fecha": "2026-11-20T18:42:07.512Z"
}

Usa origen para saber quién lo envió y mensajeId para confirmar el procesado.

Ciclo de entrega

Después de enviar, el emisor recibe eventos que indican en qué punto está su mensaje:

sent

Luminis aceptó el evento y le asignó un mensajeId.

delivered

Llegó a al menos una conexión del destino. Si estaba desconectado, se envía cuando reconecta.

seen

El destino confirmó que lo procesó.

EventoCuándo ocurreCampos
sentSiempre que el evento es aceptado.mensajeId, destino, ref
deliveredAl llegar al destino, al momento o al reconectar.mensajeId, destino, ref
seenCuando el destino envía la confirmación de procesado.mensajeId, origen
desaparecidoEl destino no reconectó dentro de la retención de tu plan y el evento se descartó.mensajeId, destino
desconocidoEl destino nunca se ha conectado a tu cuenta; el evento no se guarda.mensajeId, destino, ref

La cola offline guarda eventos solo para usuarios que ya se conectaron alguna vez. Conecta tus dispositivos al menos una vez para que puedan recibir eventos mientras están fuera de línea.

Confirmar procesado

Cuando el destino termina de usar un evento, puede avisar al emisor. Esta confirmación no consume peticiones de tu plan.

Trama a enviar
{ "type": "seen", "mensajeId": "3f9a1c7e2b", "destino": "sensor-01" }

En destino va el origen del evento recibido. Si el emisor está desconectado, la confirmación le llega cuando reconecta.

Presencia

Consulta si hasta 200 usuarios están conectados. Requiere el permiso consultar_presencia.

Enviar
{ "type": "presencia", "usuarios": ["ana", "dashboard"], "ref": "p1" }
Respuesta
{ "type": "presencia", "ref": "p1", "usuarios": { "ana": false, "dashboard": true } }

Ping y conexión viva

Luminis envía un ping de protocolo cada 25 segundos y cierra la conexión si no recibe respuesta en 75 segundos. Los navegadores, Postman y la mayoría de librerías responden automáticamente.

Para medir latencia o mantener viva la conexión a través de proxies, envía tu propio ping de aplicación:

Enviar
{ "type": "ping", "ref": "p1" }
Respuesta
{ "type": "pong", "ref": "p1", "hora": "2026-11-20T18:42:07Z" }

Errores

Los errores de una trama no cierran la conexión. Llegan como un evento error con el ref de la trama que lo causó:

Evento recibido
{ "type": "error", "code": "LIMITE_PETICIONES", "mensaje": "Se alcanzó el límite de peticiones del plan", "ref": "mi-id-local-123" }
CódigoMotivo
FORMATOLa trama no es un objeto JSON válido, o a seen le falta mensajeId o destino.
TIPO_DESCONOCIDOEl type no es message, seen, presencia ni ping.
DESTINO_INVALIDOFalta destino o no cumple el formato.
MENSAJE_VACIOFalta el campo mensaje.
MENSAJE_GRANDEEl evento supera el tamaño máximo de tu plan.
SIN_PERMISOLa API key no tiene el permiso necesario (enviar o consultar_presencia).
RATE_LIMITDemasiados eventos por segundo en esta conexión.
LIMITE_PETICIONESSe agotaron las peticiones del mes y tu plan no permite adicionales.

Códigos de cierre

Cuando Luminis cierra la conexión, envía antes un evento error con el motivo y luego cierra con uno de estos códigos:

CódigoMotivoQué hacer
4400Parámetro usuario ausente o inválido.Corrige el usuario.
4401API key ausente, inválida o revocada.No reconectes con la misma llave.
4402La cuenta no tiene un plan vigente.Activa o renueva el plan.
4403La API key no tiene el permiso conectar.Edita los permisos de la llave.
4429Se alcanzó el límite de conexiones del plan o del usuario.Reintenta más tarde o amplía el plan.
1000 / 1006Cierre normal o conexión perdida.Reconecta con espera progresiva.

API REST: autenticación y respuesta

Usa la API REST desde tu backend para publicar eventos sin mantener un socket abierto. Envía tu llave en el encabezado X-Api-Key. Todas las respuestas tienen la misma forma:

Respuesta
{
  "validation": "Success",
  "status": 201,
  "data": { "mensajeId": "3f9a1c7e2b", "estado": "entregado" },
  "mensage": "Mensaje publicado"
}
HTTPSignificado
200 / 201Correcto.
400Datos inválidos (origen, destino, tamaño del evento…).
401Falta la API key o no es válida.
402La cuenta no tiene plan vigente.
403La llave no tiene el permiso requerido.
429Se alcanzó el límite de peticiones del plan.

/api/luminis/mensajes/add · permiso publicar. El origen es el nombre con el que aparecerá el emisor (por ejemplo, servidor o erp).

curl -X POST {{HTTP}}/mensajes/add \
  -H "X-Api-Key: lm_TU_CLAVE" \

  method: "POST",
  headers: { "X-Api-Key": "lm_TU_CLAVE", "Content-Type": "application/json" },

});
const { data } = await respuesta.json();
console.log(data.estado);

r = requests.post(
    "{{HTTP}}/mensajes/add",

/api/luminis/cuenta/getById · permiso consultar_cuenta. Devuelve el plan vigente, peticiones usadas y límite, límite de conexiones, conexiones en vivo y los permisos de la llave. No consume peticiones.

Ejemplos completos

function conectarLuminis({ apiKey, usuario, alRecibir }) {
  let socket;
  let espera = 1000;

  const abrir = () => {
    socket = new WebSocket(`{{WS}}?apikey=${apiKey}&usuario=${usuario}`);

    socket.onmessage = (e) => {
      const evento = JSON.parse(e.data);
      if (evento.type === "ready") espera = 1000;
      if (evento.type === "message") {
        alRecibir(evento.mensaje, evento);
        socket.send(JSON.stringify({ type: "seen", mensajeId: evento.mensajeId, destino: evento.origen }));
      }
    };

    socket.onclose = (e) => {
      if ([4400, 4401, 4402, 4403].includes(e.code)) return;
      setTimeout(abrir, espera);
      espera = Math.min(espera * 2, 30000);
    };
  };

  abrir();
  return {
    enviar: (destino, mensaje) => socket.send(JSON.stringify({ type: "message", destino, mensaje }))
  };
}

const luminis = conectarLuminis({
  apiKey: "lm_TU_CLAVE",
  usuario: "dashboard",
  alRecibir: (datos) => console.log("Nuevo dato", datos)
});

Buenas prácticas

  • Nunca expongas una llave con permisos de más. En aplicaciones de navegador usa llaves con solo conectar y enviar; reserva publicar y desconectar para tu backend.
  • Reconecta con espera progresiva. Duplica la espera en cada intento (1 s, 2 s, 4 s… hasta 30 s) y no reconectes ante los cierres 4400, 4401, 4402 y 4403.
  • Usa ref. Relaciona cada sent, delivered o error con lo que enviaste.
  • Confirma lo que procesas. Enviar seen permite al emisor saber que el dato se usó, sin coste para tu plan.
  • Usa nombres de usuario estables. La cola offline funciona por usuario: un sensor debe reconectar siempre con el mismo nombre.
  • Mantén los eventos pequeños. Envía solo lo que cambió; respeta el tamaño máximo por evento de tu plan.
